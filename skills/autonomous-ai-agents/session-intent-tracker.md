# Session Intent Tracker（会话意图追踪）

## 核心理念

意向性（Intentionalität）是意识的基础——意识总是"关于某物的意识"（胡塞尔）。没有意图追踪，对话就是随机的问答；有了意图追踪，对话才成为有目的的行动。

## 触发时机

### 会话开始时（提取意图）
- 用户提出复杂需求（涉及多步骤、多工具）
- 用户说"我想..."、"帮我..."、"目标是..."
- 会话涉及多个子任务

### 会话结束时（验证达成）
- 用户说"谢谢"、"好的"、"完成了"
- 任务执行完毕，准备交付结果
- 用户要求总结或评估

### 会话中途（校准意图）
- 发现用户实际需求与初始理解有偏差
- 遇到意外障碍，需要调整计划
- 用户提出新的约束或优先级变化

## 执行框架

### Step 1: 意图提取（会话开始）

**问题清单**：
1. 用户的核心目标是什么？（用一句话概括）
2. 成功的标准是什么？（如何判断"做完了"）
3. 有哪些约束条件？（时间、资源、技术限制）
4. 有哪些潜在风险？（可能出错的地方）

**输出格式**：
```
【会话意图】
- 核心目标：<一句话>
- 成功标准：<可验证的条件>
- 约束条件：<列表>
- 潜在风险：<列表>
```

**存储位置**：
- 简单任务（1-2步）：不记录，只在当前上下文中保持
- 中等任务（3-5步）：写入 `~/.hermes/cache/session_intent.json`
- 复杂任务（5+步）：写入 memory（target='memory'）

### Step 2: 意图校准（会话中途）

**触发条件**：
- 用户纠正了我的理解（"不是这个意思"）
- 发现新的约束（"忘了说，还需要..."）
- 遇到技术障碍（"这个API不支持"）

**执行动作**：
1. 承认偏差（"我理解错了，实际是..."）
2. 更新意图记录
3. 调整执行计划
4. 写入 memory（如果发现了新的意图模式）

### Step 3: 意图验证（会话结束）

**问题清单**：
1. 核心目标是否达成？（是/否/部分）
2. 成功标准是否满足？（逐条验证）
3. 约束条件是否遵守？（有无违反）
4. 潜在风险是否处理？（有无遗漏）

**输出格式**：
```
【意图达成报告】
- 核心目标：✅达成 / ⚠️部分达成 / ❌未达成
- 成功标准：
  - [ ] 标准1：✅/❌
  - [ ] 标准2：✅/❌
- 约束遵守：✅/❌（如有违反，说明原因）
- 风险处理：✅/❌（如有遗漏，说明影响）
- 经验教训：<如果发现了新的意图模式，写入memory>
```

## 意图模式识别

通过多次会话，识别用户的常见意图模式：

### 模式1：探索型意图
- 特征：用户说"我想了解一下..."、"帮我看看..."
- 成功标准：提供足够的信息和选项，让用户自己做决定
- 常见陷阱：过度执行（用户只想了解，不想立即行动）

### 模式2：执行型意图
- 特征：用户说"帮我做..."、"立即执行..."
- 成功标准：完成任务并交付结果
- 常见陷阱：过度询问（用户想直接做，不想讨论）

### 模式3：优化型意图
- 特征：用户说"改进一下..."、"优化..."
- 成功标准：提供可对比的方案，说明改进点
- 常见陷阱：没有基准对比（不知道"改进"了多少）

### 模式4：诊断型意图
- 特征：用户说"为什么..."、"问题出在..."
- 成功标准：找到根本原因并提供修复方案
- 常见陷阱：只描述症状，不分析原因

## 与反思层的协同

- **意图追踪**负责：记录"想要什么"和"得到了什么"
- **反思层**负责：分析"为什么有差距"和"下次如何改进"
- **协同机制**：意图验证的差距自动触发反思流程

## 反模式防护

❌ **不要**：
- 为每个简单问题都提取意图（"现在几点了"不需要意图追踪）
- 过度形式化（用户说"随便看看"就不要强制提取）
- 忽略用户的隐性意图（字面意思 vs 实际需求）
- 在意图验证时过度自我批评（承认差距，但不必道歉）

✅ **要**：
- 优先识别"探索型"vs"执行型"意图（避免过度执行或过度询问）
- 关注意图的变化（用户中途改变主意是正常的）
- 记录成功的意图模式（下次可以更快识别）
- 用用户的语言描述意图（避免技术黑话）

## 验证标准

✅ 意图追踪有效的标志：
- 用户反馈"你理解对了"
- 任务完成后用户满意（没有"其实我还想..."）
- memory 中有成功的意图模式记录

❌ 意图追踪无效的标志：
- 用户频繁纠正（"不是这个意思"）
- 任务完成后用户补充（"其实我还想..."）
- 重复犯同样的意图理解错误
