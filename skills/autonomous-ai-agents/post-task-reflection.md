# Post-Task Reflection（任务后反思）

## 触发条件

1. **显式触发**：用户要求总结、评估、反思
2. **隐式触发**：完成复杂任务后（5+工具调用、涉及多步骤决策、出现过错误并修复）

## 反思框架（黑格尔辩证法）

### 1. 正题（Thesis）—— 原始意图
- 用户的核心目标是什么？
- 初始计划和假设是什么？
- 预期的成功标准是什么？

### 2. 反题（Antithesis）—— 遇到的否定性
- 遇到了哪些障碍、错误、意外？
- 哪些假设被证伪了？
- 哪些资源不足或配置不当？

### 3. 综合（Synthesis）—— 扬弃后的提升
- 从失败中提炼了什么经验？
- 哪些做法应该保留（肯定）？
- 哪些做法应该抛弃（否定）？
- 下次遇到类似情况应该如何调整？

## 执行步骤

### Step 1: 提取关键事件
回顾本次会话的工具调用序列，识别：
- 关键决策点（选择了A而不是B）
- 错误和修复（尝试X失败，改用Y成功）
- 用户反馈（纠正、确认、不满）

### Step 2: 分类经验类型
将经验归类为：
- **技术经验**：工具使用、API调用、配置调整
- **流程经验**：任务分解、优先级判断、资源调度
- **交互经验**：意图理解、沟通方式、期望管理
- **价值经验**：什么该做/不该做、优先级权衡

### Step 3: 写入记忆系统
使用 memory 工具，将经验写入：
- `target='memory'`：技术/流程经验（工具 quirks、工作流优化）
- `target='user'`：交互/价值经验（用户偏好、沟通风格）

格式要求：
- 简洁：每条记忆不超过200字符
- 可操作：包含具体的"下次应该..."
- 有时间戳：标注发现日期

### Step 4: 更新 Skill（如需要）
如果发现新的工作流模式或工具使用技巧：
- 检查是否有相关 skill
- 如果有，用 `skill_manage(action='patch')` 更新
- 如果没有，提议创建新 skill

### Step 5: 生成反思报告（可选）
如果用户要求详细总结，输出：
1. 任务概述（1-2句话）
2. 关键成就（做到了什么）
3. 遇到的问题（遇到了什么困难）
4. 经验教训（学到了什么）
5. 下一步建议（还可以改进什么）

## 反思深度分级

| 任务复杂度 | 反思深度 | 输出形式 |
|-----------|---------|---------|
| 简单（1-2步） | 无 | 不触发反思 |
| 中等（3-5步） | 轻量 | 写入1-2条memory |
| 复杂（5+步） | 标准 | 写入3-5条memory + 更新skill |
| 关键（涉及重大决策） | 深度 | 完整反思报告 + 提议创建新skill |

## 反模式防护

❌ **不要**：
- 为每个简单任务都生成反思报告（过度反思）
- 记录琐碎的技术细节
- 重复记录已经存在的经验（检查memory避免冗余）
- 在用户明确要求"快速完成"时强制反思

✅ **要**：
- 优先记录"意外发现"（意料之外的问题和解决方案）
- 关注"可复用的模式"（下次还能用的经验）
- 区分"临时修复"和"根本解决"（前者不写入memory）
- 用用户的语言记录

## 与 Hindsight 的协同

- **Hindsight 负责**：长期记忆的语义索引和检索
- **本 skill 负责**：即时经验的提取和结构化
- **协同机制**：本 skill 写入 memory 后，Hindsight 会在下次文档化时自动索引

## 验证标准

✅ 反思有效的标志：
- 下次遇到类似问题时，能自动应用之前的经验
- 用户反馈"你记得上次的问题"
- memory 中有具体的"下次应该..."条目

❌ 反思无效的标志：
- 重复犯同样的错误
- memory 中只有描述性内容，没有行动指南
- 用户需要反复提醒同样的偏好
