# 拷问面试

统一入口：覆盖逐个提问、批量前沿、工作流设计三种拷问模式。

## 场景决策树

```
开始
├─ 需要压力测试一个计划/决策？ → 逐个提问模式（grilling）
├─ 需要同时探索多个前沿问题？ → 批量前沿模式（batch-grill-me）
└─ 需要设计可重复的工作流？ → 工作流设计模式（loop-me）
```

## 一、逐个提问模式（grilling）

**适用**：压力测试计划、决策或想法  
**触发**：用户说 "grill me"、"stress-test"、"interview me about..."

### 核心纪律

无情地采访我关于这方面的每个方面，直到我们达成共同理解。沿着决策树的每个分支走，逐个解决决策之间的依赖关系。对每个问题，提供你的推荐答案。

### 工作流程

1. **一次问一个问题**，等待每个问题的反馈后再继续。一次问多个问题令人困惑。

2. **如果事实可以通过探索环境找到**（文件系统、工具等），查找它而不是问我。*决策*是我的——把每个决策交给我并等待我的答案。

3. **不要行动**，直到我确认我们达成了共同理解。

4. **走决策树的每个分支**，解决依赖关系：
   - 识别当前可以问的问题（前提条件已解决）
   - 提供推荐答案
   - 等待用户回答
   - 根据回答重塑树，推进前沿

5. **完成条件**：决策树的每个分支都已访问，没有默默假设的东西留下。

## 二、批量前沿模式（batch-grill-me）

**适用**：需要同时探索多个前沿问题，快速推进设计树  
**触发**：用户说 "batch grill me"、"ask everything at once"

### 核心纪律

将设计映射为**设计树**：每个决策分支出依赖它的决策。

按**轮次**工作。**前沿**是每个前提条件已解决的决策——你现在可以问的问题，而不必猜测你还没听到的答案。

### 工作流程

1. **一轮问整个前沿**：编号每个问题并给出你的推荐答案。然后等待用户的回答再进行下一轮。

2. **每轮用户回答重塑树**——解决的决策将前沿向外推进，解锁依赖它们的问题。重新计算前沿并问下一轮。

3. **一个问题的答案依赖本轮仍开放的另一个问题**属于*后续*轮次，不是本轮。

4. **查找事实是你的工作**，永远不是用户的。当前沿问题需要环境中的事实（文件系统、工具等）时，派遣子代理查找它——不要问用户你可以自己查找的任何东西。

5. **不要在它上面阻塞**：运行的探索是未解决的前提条件，所以只有它下游的问题等待子代理报告——问前沿的其余部分现在。

6. **决策是用户的**——把每个交给他们并等待。

7. **完成条件**：前沿为空：设计树的每个分支都已访问，没有默默假设的东西留下。不要在用户确认达成共同理解前行动。

## 三、工作流设计模式（loop-me）

**适用**：设计可重复的工作流规范  
**触发**：用户说 "design a workflow"、"spec a loop"、"loop me"

### 核心纪律

运行有状态的 `/grilling` 会话，其唯一输出是**工作流**规范。使用 grilling 纪律——无情、一次一个问题、每个附带推荐答案——针对下面的词汇和目标。随着 grilling 解决事情，创建、编辑和删除规范。

### 循环透镜

**循环**是用户生活中的重复模式：他们的职业、他们的周、他们的早晨、单个重复活动。将生活视为循环中的循环揭示其活动有多可预测——这就是什么使它们值得**委托**。使用透镜找到值得规范的循环，并提议用户没注意到的循环。

**工作流**是一个循环的规范，使其真实。你在循环上运行工作流——循环是其运行实例。工作流存在于 `workflows/*.md` 中，是真实来源。

### 词汇

共享语言，只有在工作流需要时才使用——永远不是清单。**不强制任何结构**：工作流不需要 AI、检查点或时间表，除非 grilling 显示它需要。

- **触发器** — 什么触发每次运行：**事件**（新邮件、新问题）或**时间表**（每天早上）。事件触发通常更高效。
- **检查点** — 人在环中的点，用户被要求验证或决策。一些工作流没有检查点并自主运行；一些根本不使用 AI。
- **向右推** — 尽可能推迟检查点。在涉及人类之前做最大工作，所以他们被问一次，晚些，一切都准备好了。
- **简报** — 检查点呈现什么：紧凑的、决策就绪的摘要——生产了什么、为什么，以及到资产本身的链接——永远不是原始输出。用户读简报，不是草稿。审查速度至关重要。

### 完成定义

工作流规范完成当实现者代理可以在不问任何问题的情况下构建它。Grill 到那时；当问题留下时 nothing is done。

### 工作区

- `workflows/*.md` — 每个工作流一个规范。
- `NOTES.md` — 关于用户世界的原始笔记：他们使用的工具、他们处理的渠道，以及他们自己的术语。当它为空或薄时，在规范任何东西之前采访他们关于他们的世界。随着模糊术语出现时将其锐化为规范术语，并记录在这里。

## 四、常见陷阱汇总

### 逐个提问模式
- **一次问多个问题** — 令人困惑，一次一个
- **不查找事实** — 如果可以通过探索环境找到，查找它
- **过早行动** — 等待用户确认共同理解

### 批量前沿模式
- **阻塞在事实查找上** — 派遣子代理查找事实，不要阻塞前沿
- **混合轮次** — 依赖本轮仍开放问题的问题属于后续轮次
- **不重新计算前沿** — 每轮后根据用户回答重新计算

### 工作流设计模式
- **强制结构** — 不强制任何结构，让 grilling 显示需要什么
- **不锐化术语** — 随着模糊术语出现时将其锐化为规范术语
- **不完整规范** — 规范完成当实现者可以在不问任何问题的情况下构建它
